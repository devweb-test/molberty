# Архитектура WordPress

## Рекомендуемая схема

WordPress + WooCommerce + собственная классическая тема molberty + собственный плагин molberty-core. Редактируемые секции — нативные блоки Gutenberg и поля сущностей. Не использовать визуальный конструктор как способ заменить согласованный интерфейс.

Тема отвечает за разметку, CSS, JS-взаимодействия и общий стиль. molberty-core отвечает за бизнес-правила, точную маршрутизацию, расчёт цены, поля и обработку заявок. WooCommerce отвечает за товары, сессии, корзину, заказы и их административный учёт.

Использовать API WooCommerce для заказа и товара, не писать заказы SQL-запросами в wp_posts: итоговая реализация должна работать с выбранным режимом хранения WooCommerce. Совместимость с HPOS проверить в установленной версии.

## Важные решения

- Товары — WooCommerce product. Исходные id/sourceId хранятся отдельно от WordPress ID.
- Административные CPT: molberty_client, molberty_review и molberty_case. После первоначального импорта перенести их регистрацию в molberty-core и отключить вспомогательный плагин; сами записи и meta остаются в базе.
- Не создавать тысячи вариаций механически. Изделие остаётся одним товаром, опции сохраняются в структурированных полях. Рассчитать итог через проверяемый серверный адаптер.
- Вспомогательный импорт создаёт WC_Product_Simple с базовой ценой и исходными опциями в meta, исключительно в черновиках. Он не реализует окончательное ценообразование.
- Категории — product_cat с иерархией; публичные адреса категорий лежат в корне сайта. Маршруты регистрируются по явному списку 34 slug, чтобы не перехватить /contacts/, /prices/, /blog/ и другие страницы.
- Статьи — обычные post; постоянная ссылка /blog/%postname%/. Страницы /blog/ и /catalog/ назначаются соответствующими страницами после подготовки шаблонов.
- Клиенты, отзывы, примеры проектов — отдельные редактируемые сущности. Не смешивать 49 клиентов со списком 3 примеров пространств.
- Контакты, режим работы, документы, реквизиты, стандарты и ссылки — единые настройки. Их используют главная, контакты, доставка, шапка и футер.
- Для кейсов/следующего блока использовать готовые Gutenberg-контейнеры из wordpress/molberty-home-blocks.zip. Внутренние карточки редактируются стандартными блоками; видимость переключается независимо.
- CSV из tables — таблицы сверки, а не замена JSON и не файл для штатного WooCommerce CSV importer: сложные опции в CSV не представлены полностью.

## Что переносить из JS

Взаимодействия баннеров, галереи, быстрого просмотра, cookie, мобильного меню, отзывов и exit-intent можно адаптировать из эталона. Имена классов желательно сохранить. Скрипты должны получать актуальные данные WordPress и WooCommerce, а не статический window.CATALOG.

assets/app.js нельзя подключить целиком к WordPress: он генерирует интерфейс, меняет document.title и хранит собственную корзину. Разделить его на небольшие модули и удалить повторный вывод HTML/SEO. Каждый интерактивный блок подключать только на нужных страницах.

## Медиа

Фото изделий сохраняются полностью: 202 элемента галерей у 91 изделия. Изображения, PDF и логотипы — локальные. Системные SVG, фавиконы, CSS/JS и шрифты допустимо оставить в теме. Не включать глобальный небезопасный SVG upload ради логотипа; доверенные SVG из эталона переносить как файлы темы.
