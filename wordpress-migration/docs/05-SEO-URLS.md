# URL, метаданные и индексация

## Сохранить маршруты

Точное соответствие — exports/routes.json и tables/routes-seo.csv. Товары /product/slug/, категории /slug/ в корне, статьи /blog/slug/. Не добавлять product-category, category, магазин или WordPress ID в URL.

142 содержательные страницы включают 404.html. Создавать отдельную опубликованную страницу 404.html не нужно: используется 404.php с кодом 404 для неизвестного URL. Остальные 141 маршрут должны соответствовать своей сущности и отдавать 200.

Для корневых категорий использовать явный whitelist всех 34 slug и обработчик term link/query var. Проверить коллизии с 12 страницами, блогом, товарными slug и системными URL. Rewrite rules сбрасывать при активации/изменении структуры, не на каждом запросе.

## Метаданные

Точное итоговое содержимое title/description/keywords/h1 уже экспортировано из HTML. Это важнее старых черновиков таблиц. Явно заданные редактором значения сохраняются.

Шаблон товара: title = [h1] - купить, цена, описание.
Description = [h1] купить по выгодной цене от производителя Мольберты.ру. Описание и характеристики. Доставка по Москве и во все регионы России.

Для категории без отдельного значения: title = [h1] - купить с доставкой от производителя.
Description = [h1] купить по выгодной цене от производителя с доставкой по Москве и во все регионы России. Каталог, описание, характеристики.

Для каждой страницы один title, один meta description и один h1. Keywords выводятся там, где они есть в эталоне. Не вводить разделитель |, кавычки вокруг моделей и новые формулировки вместо согласованных.

Выбрать одного владельца вывода SEO: например, один установленный SEO-плагин и адаптер полей, либо molberty-core. Импорт хранит значения в нейтральном _molberty_seo; сами по себе эти поля не выводятся в head. Не ждать, что Yoast/Rank Math автоматически прочитают произвольную meta.

## Структурированные данные

Organization, Product/Offer и BreadcrumbList выводятся сервером один раз. Product.name берётся из h1, Product.description — из meta description. Организация имеет согласованное описание из settings.json.

URL и @id строятся от реального home_url; logo/image указывают на действительные локальные файлы или медиатеку. Цену и валюту RUB синхронизировать с продаваемой комплектацией. Если доступно только значение От, не объявлять произвольную точную цену; проверить корректную модель Offer/AggregateOffer под реальные данные. Не заявлять наличие, рейтинг или отзывы о товаре без источника этих сведений.

Проверить JSON-LD синтаксически и в актуальных валидаторах Schema.org/Google после реализации. Старые QA-отчёты эталона не являются проверкой новой темы.

## Редиректы

exports/redirects.json содержит 76 переходов прототипа и 15 известных адресов старого сайта: всего 91 точное правило. Заготовки Nginx/Apache в integration/ применяются только после проверки домена и конфликтов.

Это не полный обход действующего старого сайта. До переключения выгрузить его sitemap, доступные URL из аналитики/вебмастера и важные внешние посадочные страницы; дополнить redirects с точным соответствием. Не отправлять все отсутствующие страницы на главную.

Фрагмент #!/tproduct/ не передаётся серверу. Для 91 известной старой ссылки есть exports/legacy_fragments.json и браузерный адаптер integration/legacy-fragments.js. Он должен работать и на новых страницах категорий после серверного редиректа. Сам по себе 301 /for_artist не переводит посетителя на конкретный товар. На реальном старом сайте дополнительно проверить ссылки из других списков и Tilda record ID.

## Staging и production

Весь прототип содержит noindex,nofollow. На staging запрет оставить; желательно также HTTP-аутентификацию. На production снять глобальный запрет только после готовности. Не копировать robots.txt/robots meta прототипа как итоговую конфигурацию боевого сайта.

Комментарии noindex внутри отдельных согласованных блоков сохраняются; это отдельное требование и не замена robots. Cart, checkout, внутренние результаты поиска и служебные endpoints не включать в sitemap.

Canonical на публичном сайте https://www.molberty.ru; никакого devweb-test.github.io/molberty/new-site или staging в head, JSON-LD и sitemap. Генерировать sitemap из опубликованных сущностей WordPress, исключив redirects/404.

## Проверка из комплекта

    python3 tools/check_target.py --base https://staging.example.invalid --mode staging
    python3 tools/check_target.py --base https://www.molberty.ru --mode production --check-redirects

Скрипт сравнивает URL, статус, title/description/keywords/h1 и базовые признаки JSON-LD, проверяет robots/canonical и неизвестную страницу. Это проверка HTML, а не замена Lighthouse, браузерной приёмки или серверных тестов цен.
