# Формы, корзина и заказы

## Семь сценариев

| Сценарий | Поля и поведение |
| --- | --- |
| Общий запрос | Имя, контакт для ответа, описание задачи, обязательное согласие |
| Заказать звонок | Имя, телефон, удобное время, согласие |
| Выход курсора | Те же поля обратного звонка, отдельный источник заявки |
| Оформление корзины | Имя, телефон, e-mail, способ получения, город/адрес при доставке, состав с фото и итогом |
| Подбор интерьерного мольберта | Габариты картины, высота экспозиции, вес и глубина рамы; затем контакты и согласие |
| Оптовая форма | Организация, имя, телефон, e-mail, состав заказа, необязательный адрес, согласие |
| Розничная форма | Имя, телефон, e-mail, состав заказа, необязательный адрес, согласие |

У опта и розницы формы стоят прямо на /contacts/ и /delivery/. В обоих блоках указан molberty@gmail.com. Поле ИНН и реквизиты удалено. Не добавлять обязательную авторизацию ради отправки запроса.

## Единый компонент

Подписи и согласие 14 px; поля 16 px; фон белый; outline-offset 0 у input/textarea; прямые углы; кнопка Отправить. Заголовки форм — div/span. Согласие не предустановлено; ссылки /privacy/ и /consent/ открываются без потери ввода.

В статическом эталоне отправки нет. Текст демонстрационного результата заменить реальным результатом серверной операции после подключения обработчика, сохранив оформление. Не показывать Ваш запрос отправлен только из-за прохождения browser validation.

## Серверный обработчик

Проверять nonce и контекст запроса, обязательные поля, формат e-mail/телефона, длины строк и согласие; применять rate limit, защиту от повторов и спама. Не доверять произвольным HTML, адресу получателя или значениям товара из POST.

Получатель уведомлений берётся из серверной настройки, по умолчанию molberty@gmail.com. Настроить авторизованный SMTP/транзакционную почту с адресом своего домена; контакт посетителя ставить Reply-To после проверки, не From. SMTP-ключи не хранятся в Git. Журнал заявок должен быть доступен только уполномоченным пользователям.

Успех: заявка/заказ сохранены, сформирован идентификатор, результат отправки известен. При частичном сбое уведомления не создавать дубликат заказа при повторе; показать оператору сбой, посетителю достоверное состояние.

В согласии фиксировать факт, время, версии/URL политики и согласия и назначение формы. Срок хранения данных и уведомлений задаёт оператор; не изобретать бессрочный технический журнал.

## Корзина

Использовать сессию WooCommerce. В каждой строке стабильный productId/sourceId, режим цены, допустимые индексы опций и количество. Ключ строки различает разные комплектации и режимы. Денежные значения пересчитываются сервером.

Заказать из списка не открывает форму, обновляет счётчик и уведомление. Быстрый просмотр и подробная карточка работают с той же ценовой функцией. Кнопки удаления заметны, имеют Удалить из корзины при наведении; есть Очистить корзину.

Состав заказа содержит изображение, название, опции, режим цены, количество и Итого за изделия. Доставка по Москве, в регионы или самовывоз бесплатно. Внешне это три чекбокса, но сервер принимает только один вариант.

Город и адрес обязательны для доставки, не требуются для самовывоза. Доставка, ещё не рассчитанная оператором, не должна превращаться в фиктивный бесплатный shipping rate. Приписка: Стоимость доставки варьируется от вашего адреса, региона и способа доставки. Доставку согласуем при оформлении заказа.

Оформление без онлайн-оплаты на первом этапе — заказ с последующим согласованием. Сообщение посетителю должно описывать регистрацию заказа, а не оплату или подтверждение наличия.

## Cookie и exit-intent

Cookie: компактное окно, текущий текст, ссылки privacy/consent, кнопка Согласен, сохранение выбора. Согласие на cookie и согласие конкретной формы не смешивать.

Exit-intent: только указатель мыши на устройствах с hover, не ранее 8 секунд; закрывшему не показывать повторно 6 минут, новое появление требует нового выхода курсора. Учитывать другие диалоги, фокус ввода, меню и скрытую вкладку. На телефоне без мыши автопоказ отсутствует. beforeunload не перехватывать.
